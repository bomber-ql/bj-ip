# 内容分层规范

本站同时服务两类读者：**人**和**机器**（搜索引擎爬虫、AI 抓取器）。两类读者的需求不同，但**看到的东西必须一样**。

这是整份规范的唯一底线。所有分层都建立在它之上：可以为了机器做额外的结构化表达，但不能出现"机器看到 A、人看到 B"。

---

## 四层模型

### L1 人读层 —— 页面主体

用户真正要看的内容。服务说明、案例描述、文章正文、常见问题。

- 必须在初始 HTML 里（不能靠 JS 二次拉取）
- 必须有观点、有具体信息，不能是段落级的同义反复
- 判断标准：**把浏览器里的 JS 全关掉，这一层应该完整存在**

### L2 人机共用层 —— 结构化但可见

同一份内容，用更容易被抽取的方式再组织一遍。**人看着更清楚，机器读着更明确，两边看的是同一批字。**

本站已落地的形式：

| 形式 | 位置 | 人得到什么 | 机器得到什么 |
|---|---|---|---|
| 本文要点（带锚点目录） | 每篇文章顶部 | 快速判断要不要读、直接跳到关心的节 | 明确的小节边界，可按节引用 |
| 面包屑 | 全部内页 | 知道自己站在站点哪一层 | `BreadcrumbList` + 层级关系 |
| 交付清单（分块卡片） | 服务页 | 一眼看清能拿到什么 | 可枚举的服务项 |
| FAQ 折叠问答 | 服务页、联系页 | 先扫问题再决定展开哪个 | `FAQPage`，可直接作为答案引用 |
| 定义式导语 | 服务页 `.lead` | 三句话知道这块业务是什么 | "X 是指……"的可摘句 |
| 数据胶囊 | 首页 | 规模和能力一眼可见 | 可引用的具体数字 |

原则：**L2 不允许出现 L1 里没有的信息**。目录只能列正文真实存在的小节；FAQ 只能是页面上真回答过的问题。

### L3 声明层 —— 不可见，但不违规

只有机器读、人不需要看见的东西。它们之所以合规，是因为它们是**标准的元数据声明**，不是藏起来的内容。

- `title` / `meta description` / `canonical`
- Open Graph / Twitter Card
- JSON-LD（`Organization` / `WebSite` / `Service` / `Article` / `FAQPage` / `BreadcrumbList`）
- `sitemap.xml` / `robots.txt`
- `llms.txt`（给 AI 引擎的站点说明与内容索引）
- 响应头：缓存、安全策略

**L3 的铁律：只声明 L1/L2 里已经存在的东西。**

写 schema 时问自己一句：这句话在页面上找得到吗？找不到就删掉 schema 里那句，或者把它补进正文——不能只在 schema 里说"我们做礼品和展览展示"，页面上却一个字没有。这属于"结构化数据与可见内容不符"，是明确的质量问题。

审计脚本里的 `结构化数据里的说法在正文找不到` 就是查这个。

### 红线层 —— 一律不做

以下手法短期可能有效，但属于明确的作弊信号，一旦被识别就是整站级别的降权，且很难恢复：

- **隐藏文本**：`display:none`、`visibility:hidden`、`font-size:0`、`text-indent:-9999px`、与背景同色的文字、`opacity:0`、零高度容器
- **Cloaking**：对爬虫返回一套 HTML，对用户返回另一套（含 UA 判断、IP 判断）
- **`<noscript>` 里塞正文**：伪装成"给不执行 JS 的爬虫看"，实际是隐藏内容
- **Doorway page**：为每个关键词批量生成内容雷同的落地页
- **批量 AI 低质页**：几十篇结构相同、只是替换行业词的文章
- **隐藏链接 / 互链农场**
- **`meta keywords`**：早已废弃，如今更像是堆词的证据
- **锚文本堆词**：所有内链都用同一个商业词

判断标准只有一条：**如果这段内容被用户看到，你会不会觉得尴尬？** 会，就不要放。

## 实操检查清单

新增或修改页面后，按顺序过一遍：

1. **关 JS 看一遍**：内容还在吗？导航链接还在吗？
2. **看 L2 是否越界**：目录、FAQ、清单里的每一项，正文里都能找到对应内容吗？
3. **看 L3 是否说谎**：schema 里的 name / description / address，页面上能对上吗？
4. **看是否有隐藏痕迹**：有没有为了排版方便把文字藏起来？
5. **跑审计**：`python3 scripts/seo-audit.py`
6. **看红线是否为 0**

## 关于 GEO 的一个常见误解

很多人以为 GEO 就是"往页面里塞更多关键词让 AI 记住你"。

恰恰相反。AI 引擎引用一个页面，靠的是**这段内容能不能独立成立**：有没有明确的定义句、有没有可验证的具体信息、结构是不是清楚到可以切片。堆词对 AI 反而有害——它会降低信息密度，让模型判断这是低质页面。

所以真正有效的 GEO 做法，和"给机器看"其实是同一件事：

- 把观点写清楚，而不是把关键词写多
- 用定义句开头（"品牌策略解决的是一个很朴素的问题……"）
- 用具体数字替代形容词（"80 余人、8 年经验、200+ 企业"而不是"丰富经验、众多客户"）
- 把长文切成有标题的小节，每节能独立讲完一件事
- 页面上有的，schema 里才写

本站的「本文要点」就是这个思路的落地：它是一个人也能用、机器也爱读的结构，而不是一个藏起来的 div。
